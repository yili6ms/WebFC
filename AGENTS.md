# Repository instructions

These instructions apply throughout this repository.

## Project conventions

- WebFC is a static Vite web app, deployed to Vercel, that plays Famicom / NES ROMs in the browser.
- Emulation comes only from the [VisualFC](https://github.com/yili6ms/VisualFC) WebAssembly core. Do not add another emulation engine; fix or extend emulation upstream in VisualFC and rebuild the core.
- `src/core/` is generated by `npm run build:core` from the commit pinned in `visualfc.ref`. Do not edit it by hand. Commit the regenerated files with the updated `visualfc.ref`.
- ROMs are read locally in the browser and must never be uploaded or sent to a server.
- Keep frontend modules small and focused (`runner.js`, `input.js`, `touch.js`, `display.js`, `rom.js`), with `main.js` doing the DOM wiring.
- Keep desktop (keyboard, gamepad) and mobile (touch, portrait/landscape) behavior working together.
- Update `README.md` when controls, setup, deployment, or supported behavior change.

## Validation

Check the working tree before you make changes, and leave other people's work alone. Before you finish, review the diff and run:

- `npm test` for unit tests.
- `npm run build` to confirm the production build works.
- For UI, input, or layout changes, also test in a browser (desktop, and mobile emulation for touch/layout changes) when possible.
- Documentation-only changes: review the content and run `git diff --check`.

## Commits

- Commit locally after each completed task that changes repository files. Stage only that task's files; do not use `git add .` or `git add -A`.
- Use a descriptive message with a prefix such as `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, or `ci:`.
- **Authorship:** the repository owner's configured Git identity must be the only author. Do not add `Co-authored-by` trailers or other attribution to an agent or tool, and do not change the Git identity.
- Do not amend or rewrite commits, push, tag, or publish unless asked.
